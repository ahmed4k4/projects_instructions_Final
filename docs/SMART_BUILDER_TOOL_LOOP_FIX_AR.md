# إصلاح مشكلة AI temporarily unavailable في Smart Builder

## السبب الجذري الذي تم إصلاحه

كان Smart Builder يرسل عدة استدعاءات متوازية للأداة نفسها `list_components` (مثل CPU وGPU واللوحة الأم)، ثم يحوّل كل نتيجة إلى رسالة `user` مستقلة. واجهة Gemini تتعامل مع نتائج الاستدعاءات المتوازية باعتبارها مجموعة ردود داخل دور user واحد. تقسيمها إلى أدوار متتالية كان يفسد تسلسل المحادثة ويمنع النموذج من إكمال دورة الأدوات والوصول إلى `finalize_build`.

كان هناك خطأ إضافي في المحول: ربط رد الأداة بمعرّف اصطناعي مبني على اسم الأداة، بدل الحفاظ على معرّف الاستدعاء الأصلي. وعند تكرار `list_components` كانت النتائج معرضة للربط بالاستدعاء الخطأ.

## التعديلات

1. تجميع جميع `functionResponse` المتوازية داخل رسالة `user` واحدة.
2. الحفاظ على معرّف Gemini الأصلي لكل رد، وعدم اختراع معرّف إذا لم يرسله النموذج.
3. تشغيل Smart Builder باستخدام `generateContent` غير المتدفق أثناء دورات الأدوات للحفاظ على `functionCall` و`thoughtSignature` بالكامل.
4. زيادة سقف مخرجات النموذج إلى 3072 token لتقليل قطع استجابة البناء قبل الإنهاء.
5. عند انتهاء النموذج بنص عادي بعد استعراض الكتالوج، يتم إجراء محاولة نهائية مع `toolConfig.functionCallingConfig.mode = ANY` والسماح بـ `finalize_build` فقط.
6. إذا لم يبدأ النموذج باستدعاء الأدوات، يفرض النظام استدعاء `list_components` مرة استرداد واحدة بدل تكرار طلب نصي في وضع AUTO.
7. إضافة فحوصات انحدار بدون الحاجة إلى تثبيت مكتبات المشروع.

## التحقق

شغّل:

```bash
node --experimental-strip-types scripts/verify-build-agent-regressions.mjs
```

أو:

```bash
pnpm verify:build-loop
```

ثم تحقق من المشروع بعد تثبيت الاعتماديات:

```bash
pnpm install
pnpm typecheck
pnpm test
pnpm build
```

## ملاحظة تشغيلية

هذه التعديلات تصلح أخطاء تنسيق tool-calling ودورة المحادثة داخل التطبيق. لا يمكنها تجاوز نفاد حصة Gemini أو مفتاح API غير صالح أو عدم وجود منتجات في الكتالوج. إذا استمرت رسالة fallback بعد نشر هذه النسخة، راجع Vercel Function Logs لطلبات `/api/ai`؛ يجب فحص رمز HTTP ورسالة Google الأصلية لمعرفة هل السبب حصة/مفتاح/موديل أم تحقق توافق. لا تضع `GEMINI_API_KEY` في الواجهة أو في مستودع Git.
